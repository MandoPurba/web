## Context

Universitas Terbuka's graduation screening service evaluates thousands of students per study program every graduation period.

It runs on the national university platform serving 800K+ students. The current version uses cron workers on a database job queue; it is being redesigned as a Go worker on a Postgres-backed queue.

## Problem

- Screening a whole study program inside an API request runs into timeouts.
- Screening depends on legacy PHP grading servers, so calls to them need bounded concurrency and timeouts.
- Reads from a replica can lag behind the primary, which is not acceptable for graduation decisions.

## Approach

The first version moved screening out of the request path into cron workers on a database job queue, avoiding API timeouts.

The redesign as a Go worker on a Postgres-backed queue adds:

- **Atomic batch claiming.** Workers claim batches of jobs atomically, so no batch is processed by two workers.
- **Per-student fan-out.** A batch is split into one unit of work per student.
- **Lease-based recovery.** Claimed work carries a lease; if a worker stops, the work becomes claimable again once the lease expires.
- **Retries with backoff.** Failed work is retried with backoff.
- **Resumable batches.** Interrupted batches resume without reprocessing.

- **Queue:** Postgres-backed job queue.
- **Worker:** Go service that claims batches and fans out per student.
- **Grading:** legacy PHP grading servers, called with per-host concurrency limits and timeouts.
- **Reads:** decision-critical reads go to the primary database; TODO: which reads use replicas.

## Key decisions & trade-offs

- **Postgres as the queue.** TODO: why a Postgres-backed queue was chosen over a separate broker.
- **Per-host concurrency limits and timeouts.** Each legacy PHP grading server gets its own limit and timeout, so one slow server does not stall the rest. The trade-off is that total throughput is capped by those limits.
- **Primary reads for decisions.** Decision-critical reads are routed to the primary to avoid replica lag, trading extra load on the primary for consistent results.
- **Leases over locks held for the whole job.** TODO: lease duration and renewal.
